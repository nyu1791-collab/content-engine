Claude Codeを利用していると、セッションごとの会話記録がローカル環境にファイルとして保存されます。この会話記録は放置していると自動的に削除される仕組みになっています。

本記事では、エンジニアのnumarn氏による検証記事「Claude Code の会話履歴が消える日数を4か所に別々に書いたら、--settings が勝った(既定は30日)」で公開された実測データをもとに、履歴が消えるまでの日数や設定の優先順位、削除処理が動く条件について解説します。

## Claude Codeの履歴削除機能で何ができるか

Claude Codeでは、会話履歴の保存期間を制御する設定項目として `cleanupPeriodDays` が用意されています。この項目を指定することで、指定した日数を過ぎた古いセッション記録ファイルを自動的にクリーンアップ（削除）できます。

検証環境（Claude Code 2.1.305 / claude-sonnet-5-5）での実測によると、この設定には明確な既定値と優先順位が存在することが確認されています。

## 主な特徴と実測から判明した挙動

検証記事で明らかになった主な仕様と挙動は以下の通りです。

### 既定の保持期間は「30日」
設定を何も記述しない場合、既定値（デフォルト）として30日が適用されます。検証では、日付をずらした記録ファイルを配置したところ、29日前までのファイルは残り、30日・31日・45日前のファイルが削除されたことが確認されています。

削除判定の境界線は日付の切り替わりではなく、「設定日数 × 24時間」となっています。7日設定時の分刻みの検証では、最終更新から「6日23時間59分前」のファイルは残り、「7日00時間01分前」のファイルが消えるという結果が得られています。

### 設定場所の優先順位（強い順に完全上書き）
`cleanupPeriodDays` は複数の場所に設定ファイルを配置できますが、競合した場合は値の大小（日数の長短）に関係なく、より優先度の高い設定場所の値で上書きされます。

優先順位の強い順は以下の通りです。

1. 起動時オプション: `--settings <file>`
2. 作業フォルダのローカル設定: `<作業フォルダ>/.claude/settings.local.json`
3. 作業フォルダの共通設定: `<作業フォルダ>/.claude/settings.json`
4. ユーザー全体の設定: 本来は `~/.claude/settings.json`

4か所に異なる値（30、7、2、1）を同時に指定した場合、最も優先度の高い `--settings` で渡した「1」が適用され、1日前以降のファイルのみが削除されました。

### 削除対象の判定基準は「ファイルの更新時刻」
記録ファイル内のテキストに書かれた日時ではなく、ファイルシステム上の「更新時刻」をもとに削除判定が行われます。中身が45年前の日時であっても更新時刻が1日前であれば残り、逆に中身が新しくても更新時刻が45日前であれば削除されます。

なお、中身が0バイト（空）のファイルは45日前であっても削除されず、1バイト以上書き込まれているファイルのみが削除対象となります。

## 使い方と設定例

設定を行う際は、対象のJSONファイルに `cleanupPeriodDays` を数値型で指定します。

### settings.json の記述例
```json
{
  "cleanupPeriodDays": 7
}
```

### 起動オプションでの指定例
特定の実行時のみ設定を変更したい場合は、`--settings` 引数にファイルを渡します。
```bash
claude --settings custom-settings.json
```

※検証時は `CLAUDE_CONFIG_DIR` 環境変数を使い捨てディレクトリに指定し、本番の `~/.claude/` を汚さない安全な環境で確認が行われています。

## どんな人に向くか

- プロジェクトごとに会話ログの保持期間を厳密に分けたい開発者
- ディスク容量を節約するために、頻繁に古い会話履歴を片付けたい人
- チーム開発で `.claude/settings.json` を共有し、履歴管理のルールを統一したい組織

## 注意点

実務で自動化や設定を行うにあたり、いくつか注意すべき仕様が確認されています。

### 短命なプロセスでは掃除が実行されない
自動クリーンアップは起動の数秒後にバックグラウンドで動作するため、プロセスの実行時間が短すぎると削除が走る前にプロセスが終了してしまいます。
検証結果では、`claude --version` や短時間（約3秒〜5.78秒）で終了する実行では削除が行われず、約5.95秒以上実行が継続したプロセスで初めて削除が実行されました。

### 一度実行されると目印ファイルが作られる
一度クリーンアップが走ると、設定フォルダ内に `.last-cleanup` という日時の記録されたファイルが生成されます。このファイルが存在する間は、短時間のうちに再起動しても連続して掃除処理は走りません。

### 設定の書き間違いで「掃除自体が止まる」
数値を `"7"` のように文字列で囲む、小数を入力する、JSONの構文エラーを起こすといった不適切な記述をした場合、安全側の既定値（30日）に戻るのではなく、**設定ファイルの読み込みがスキップされて掃除処理自体が停止**します。

このときエラーメッセージは標準エラー出力に出ますが、**プロセスの終了コードは 0（正常終了）** のままとなります。CI/CDや自動スクリプトに組み込んでいる場合、異常終了として検知できないため注意が必要です。

一方で、`cleanupPeriodDay` のようにキー名を間違えた場合は、警告なしで既定の30日がそのまま適用されます。

## まとめ

Claude Codeの会話記録は、既定で30日（正確には30 × 24時間）保持された後に自動削除されます。日数を変更したい場合は `--settings` や各 `settings.json` の `cleanupPeriodDays` で調整可能です。設定値の誤りがあると終了コード0のまま処理が止まるため、設定変更時は構文や型に誤りがないか確認しておくことが推奨されます。
