## 何が起きたか（要点3つ）

- **同一仕様のWebアプリをAIに構築させるベンチマークが公開**：開発者のNolan Lawson氏が、Claude Code（Opus 5.5想定）を用いて各種JavaScriptフレームワークでポケモン情報アプリを実装させ、開発コストを測定しました。
- **フレームワーク間でAPIコストに約1.8倍の開きが発生**：5回の試行の中央値において、最も低コストだった構成はHono+htmx（2.67ドル）で、最も高コストだったAngular（4.97ドル）との間に明確な差が確認されました。
- **コスト差の原因は学習データの鮮度やコード量**：最新ドキュメントの読み込みや、フレームワーク固有の構造・コードサイズが、AIが消費するトークン量（利用料金）に大きく影響していました。

## 背景：なぜこの検証が行われたのか

Webフロントエンドの開発現場では、「このフレームワークは高速」「AIエージェントとの相性が良い」といった主張が、客観的なデータなしに感覚（いわゆる「vibes」）で語られる場面が少なくありませんでした。

Lawson氏はこの風潮に疑問を持ち、AIエージェント時代における客観的な指標を得るため、公平なテスト環境を用意して検証を実施しました。

### テストの実施条件
- **作成対象**：PokéAPIを利用した検索・絞り込み機能を持つポケモン情報アプリ（Wikipediaに近いコンテンツ主体の構成）
- **使用モデル**：Claude CodeのOpus 5.5（high effort設定、サンドボックス環境で動作）
- **公平性の確保**：各フレームワークの公式MCP（Model Context Protocol：AIと外部ツールを接続する仕組み）やスキルを導入し、仕様適合テストを実施して手抜きを防ぐ
- **試行回数**：確率的なブレを考慮し、原則として1フレームワークにつき5回実行して中央値を算出（Angularのみ2回の失敗を除いた3回で集計）

## 計測結果：フレームワークごとの生成コスト比較

Claude CodeのAPI価格に基づいて算出された、1回あたりの生成コスト（中央値および最小〜最大幅）は以下のとおりです。

| フレームワーク | コスト中央値（米ドル） | 範囲（最小〜最大） |
| :--- | :--- | :--- |
| Hono + htmx | $2.67 | $2.23 – $3.19 |
| Astro | $2.76 | $2.16 – $3.63 |
| Nuxt | $2.82 | $2.39 – $4.25 |
| Vanilla（素のJS） | $2.98 | $2.24 – $3.37 |
| Next.js | $3.14 | $2.58 – $4.13 |
| Qwik | $3.27 | $2.35 – $3.80 |
| TanStack Start | $3.54 | $3.11 – $3.96 |
| SolidStart | $3.79 | $2.84 – $4.81 |
| React Router | $3.81 | $2.82 – $3.97 |
| SvelteKit | $4.28 | $3.59 – $4.65 |
| Gracile + Lit | $4.65 | $3.92 – $5.07 |
| Angular | $4.97 | $3.19 – $6.82 |

### コストが高くなった主な要因

- **SvelteKit**：モデルの学習データに含まれていない最新の「SvelteKit v3移行ガイド」をエージェントが毎回読み込んだため、トークン消費が増加しました。
- **Gracile**：知名度が低くAI側の事前知識が不足していたため、リポジトリのクローンやnode_modules内のコード読み込みが発生し、費用がかさみました。
- **Angular**：生成コードの総量が大きいことや、アプリ構築の失敗（2回発生）などが影響しました。

また、公式MCPやスキルを提供していても、エージェントが毎回それらを使用したわけではない点も報告されています（例：Astro MCPの使用は5回中2回、Honoスキルは5回中5回）。

## 日本の開発者への影響・できること

AIによるコード自動生成を実務やプロトタイプ開発に取り入れる場合、以下の点を意識することが推奨されます。

- **モデルの学習済み情報とバージョンの乖離を考慮する**：最新バージョンやマイナーなツールは、AIが外部ドキュメントを大量に読み込むため、APIコストや実行時間が跳ね上がる可能性があります。
- **シンプルなスタックの優位性**：Hono+htmxやAstroなど、構成がシンプルでコード量が少なく抑えやすい技術スタックは、AIによる実装コストを低く抑えやすい傾向が見られます。
- **MCPやプロンプトの調整**：ツールを用意してもAIが活用しない場合があるため、プロンプトでの明示的な指示や不要なファイル読み込みの制限を検討する必要があります。

## 検証に関する注意点

- **単一のユースケースである点**：今回の対象はコンテンツ中心のポケモン情報アプリであり、FigmaやGmailのようなインタラクティブ性の高いアプリでの結果は未検証です。
- **LLMの確率性によるばらつき**：同じフレームワークでも試行ごとにコストの振れ幅が存在します（例：React Routerの最安値2.82ドルは、Hono+htmxの最高値3.19ドルを下回ります）。
- **実際の請求額ではない**：公表された数値はClaude CodeのAPI単価から算出された理論値であり、筆者が契約している定額プランの実費とは異なります。

## まとめ

「AIに向いている」と感覚的に語られがちだったフレームワークの選定ですが、実際のベンチマークでは、モデルの学習データの鮮度やフレームワークの複雑さがAPIコストに直接影響することが示されました。AI駆動の開発を進める際は、雰囲気での判断を避け、生成コストやツールの特性を踏まえた選定が重要になります。
