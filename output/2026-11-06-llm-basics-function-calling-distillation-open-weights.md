## LLMの周辺技術で何ができるのか

大規模言語モデル（LLM）を活用したサービスや機能が広がるなかで、「Function Calling」「オープンウェイト」「蒸留」といった専門用語を目にする機会が増えました。

これらは一見すると難解ですが、AIがどのように外部と連携し、どのようにモデルが公開・軽量化されているのかを理解するための基本的な概念です。仕組みの全体像を押さえることで、業務自動化ツールの導入やAPIを活用したアプリ開発において、モデルの選定や安全対策を適切に判断できるようになります。

## 主な特徴と基本の仕組み

### 1. Function Calling：AIは「呼び出し依頼」をテキストで出すだけ

Function Calling（Tool CallingやTool Useとも呼ばれます）は、AIが外部のサービスやAPIを利用するための仕組みです。たとえば「東京の現在の天気を教えて」とユーザーが指示した場合、LLM単体ではリアルタイムの天気を取得できません。

ここで誤解されやすいのが「AI自身が直接APIを叩いてデータを取ってきているのか」という点です。元ネタの解説によると、実際には次のような役割分担になっています。

1. アプリ側が、利用可能なツールの定義（関数名、説明、受け取る引数の形式など）をAIに事前に伝える。
2. AIは外部情報が必要だと判断すると、「このツールを、この引数で呼び出したい」という依頼の文章（JSONなどのテキスト）を出力する。
3. その依頼を受け取ったアプリ側が、実際にAPIを実行して結果を取得する。
4. アプリが取得した結果をAIに渡し、AIがそれを踏まえて最終的な回答を組み立てる。

Claudeの公式ドキュメントでは、ツールが実行される場所として以下の2種類に分類されています。

- **クライアントツール**：自作のアプリ側で処理を実行するツール
- **サーバーツール**：Web検索やコード実行など、AI提供元（プロバイダー）のサーバー側で実行されるツール

サーバーツールの場合はアプリ開発者が実行コードを書かずに済むため、AIが自律的に検索しているように見えますが、内部では「AIが依頼を出力し、システム側が実行して結果を戻す」という同一の構造で動作しています。

### 2. 画像生成の連携：別モデルを呼ぶ構成とネイティブ生成

チャットAIに「画像を生成して」と依頼したときの裏側の挙動には、大きく分けて2つのパターンが存在します。

- **パターン1：AIが別の画像生成AIをツールとして呼ぶ型**
  ChatGPTにDALL·E 3が組み込まれた当初のように、テキストを扱うAIが画像生成用のプロンプトを作成し、画像生成専用の別AI（拡散モデルなど）に処理を渡す構成です。サービス側で指示の補正や安全性チェックが挟まる場合があります。
- **パターン2：AI自身が画像を出力する型（ネイティブ画像生成）**
  OpenAIが2025年3月に発表した「4o image generation」のように、システムカードによれば自己回帰モデルによってテキストを扱うAI自身が直接画像を生成する構成です。会話の文脈や既存画像の情報をそのまま反映しやすい特徴があります。

内部の構成は提供元や世代によって異なるため、利用する際は公式ドキュメントで仕様を確認することが推奨されます。

### 3. 「オープンウェイト」と「オープンソースAI」の違い

モデルの重み（学習によって得られたパラメータの数値群）がダウンロード可能なモデルを「オープンウェイト」と呼びます。完成品のパラメータが手に入るため、自社サーバーで動かしたり、追加学習や量子化を行ったりできる利点があります。

しかし、オープンウェイトは必ずしも「オープンソース」と同義ではありません。

オープンソースの標準を策定するOSI（Open Source Initiative）が2024年に公表した「Open Source AI Definition 1.0」では、オープンソースAIと呼ぶために以下の3要素を求めています。

- **Data Information（データの情報）**：学習データの出所、範囲、処理方法などの詳細な情報
- **Code（コード）**：学習および推論・実行に利用する完全なソースコード
- **Parameters（パラメータ）**：重みなどのモデルパラメータ

学習データに関する詳細情報や学習コードが開示されず、完成した重み数値のみが公開されているモデルは、この定義ではオープンソースAIには当てはまりません。慣用句としてのオープンウェイトと厳密なオープンソースは区別して理解する必要があります。

### 4. 蒸留（Distillation）：大型モデルの能力を小型モデルへ移す手法

ニュースなどで頻繁に言及される「蒸留」とは、性能の高い大規模なAIの振る舞いを、小さく軽量なAIに学ばせる手法を指します。巨大なモデルは高精度ですが、実行コストや必要なGPUリソースが大きいため、実運用向けに小型化する目的で活用されます。

手法としては以下の2つが存在します。

- **元の蒸留手法（Hintonらの2015年論文など）**：大きなAIが出力する正解以外の選択肢を含んだ「確率の分布」を生徒役のAIに学ばせる手法。通常は教師役AIの内部数値にアクセスできる必要があります。
- **LLMで広く見られる蒸留**：高性能なAIが出力した回答テキストや思考プロセスのログを学習データとして収集し、別の小型モデルに追加学習させる手法。例として、DeepSeekが自社の「DeepSeek-R1」が生成したデータ（約80万サンプル）を用いて小型モデルを学習させた「DeepSeek-R1-Distill」シリーズがあります。

蒸留自体は自社モデルを軽量化する正当な開発手法として各社で広く使われています。一方で、競合他社のAIから大量のアカウント等を使って出力データを抽出し、自社モデルの学習に利用する行為については、Anthropicが2026年2月に発表したレポートやOpenAIの議会向けメモ報道などに見られるように、利用規約や知財の観点から議論が続いています。

## 実装・利用時の注意点

### Function Callingにおけるセキュリティ対策
AIが出力する引数の値は「信頼できない外部入力」として扱う必要があります。Prompt Injection（悪意あるプロンプトによる誤動作）への備えとして、以下の対策が挙げられています。

- **値の検証**：AIが渡してきた引数の形式、値の範囲、アクセス権限をバックエンド側で必ずチェックする。
- **確認ステップの設置**：データの削除や外部送信などの破壊的な操作を行う前に、人間やシステムの確認を挟む。
- **権限の最小化**：ツールに付与する権限は必要最小限に留める。

### オープンウェイトモデル利用時のライセンス確認
オープンウェイトモデルを利用する際は、ライセンス条項の個別確認が必須です。MITやApache 2.0のように制約が少ないものもあれば、商用利用や再配布に条件が課されている独自ライセンス（Llamaライセンスなど）もあります。

たとえば「DeepSeek-R1」自体はMITライセンスで商用利用や派生物の作成が認められていますが、それを小型モデルに蒸留した「DeepSeek-R1-Distill」シリーズは、ベースとなった元モデルのライセンス（QwenのApache 2.0やLlamaライセンス）が併記されています。シリーズ名だけで判断せず、モデルカードごとに規約を確認する必要があります。

## まとめ

- **Function Calling**：AIは実行を依頼するテキストを出力するだけであり、実際の処理はアプリや基盤側が担当する。
- **画像生成連携**：外部の専用AIを呼び出す構成と、テキストモデル自身が出力するネイティブ構成の2種類が存在する。
- **オープンウェイト**：重み数値のみが公開された状態であり、OSIの定義する「オープンソースAI」とは学習データやコード開示の面で異なる。
- **蒸留**：大型AIの出力や分布をもとに小型AIを強化する手法であり、自社開発の軽量化と他社出力の利用問題は切り離して理解する必要がある。

技術の裏側の役割分担を正しく理解し、各サービスのドキュメントやライセンスを確認したうえで適切なツール選定を行いましょう。
